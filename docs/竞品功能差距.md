## 分维结论（各 3–5 句）

### 1. 多助手 / 群聊
open-bot 已具备助手侧栏、群 @、线程、AutoPick（heuristic/decision），接近 Grok 形态。ChatGPT/Claude 更偏「单工作流 agent」或「项目多线程」，少「群里多人设互相接话」。OpenClaw 用 channel binding 做隔离路由，群内选人体验不同。**体验债**：Auto 选人需对用户可解释（本期已补「由 X 回答（自动）」）。

### 2. Skills / MCP / 市场
Skills 与 MCP CRUD/@ 引用已落地；缺 **连接器/插件市场、OAuth 池、per-bot MCP**。ChatGPT Workspace Agents 与 Claude connectors 在「一键装应用」上领先。OpenClaw 靠配置与 bundled skills，偏开发者。

### 3. 记忆
语义召回 + Mem0 + 本地 Dream 已够用；Mem0 Platform 托管与跨设备画像仍后置。Claude Projects 共享记忆、ChatGPT 记忆 UX 更「产品化」。

### 4. 多模态
用户期望「能看图、能说话」极高；我们附件无 vision、无 mic，是明显**能力债**。本期仅做诚实提示，真接入另开设计。

### 5. 本机 / 沙箱
桌面 host_* + 沙箱桌面预览已对齐 Grok 方向；Phase 3（闲置 GC、多副本）与真 computer_use 未齐。Claude Computer Use / ChatGPT Agent 浏览器在「云端操控」叙事上更强。

### 6. 例行 + 事件
Routines + Slack/GitHub webhook 可用；缺 OAuth 安装向导、quiet 不落库、分布式防重入。ChatGPT schedules 安装摩擦更低。

### 7. 渠道
**最大广度差距**：OpenClaw 覆盖 WhatsApp/Telegram/Discord/飞书等一等渠道；我们仅 Web + Hook + Gmail 出站。飞书/钉钉/Discord 等无一等 API。

### 8–12. 安全 / 多端 / 管理 / 观测 / 上手
审批与密钥已有；桌面签名、移动推送、计费、Go 侧 tracing、统一冷启动路径是剩余体验/能力债。本期 Track1 已打冷启动 CTA、无模型引导、设置重试、重新岗位引导。
