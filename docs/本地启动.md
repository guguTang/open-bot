# 本地启动

在仓库根目录操作：`/Users/tangxin/Workprojects/open-bot`（或你的 clone 路径）。

日常开发需要 **Postgres + 3 个进程**（runtime / api / web）。桌面、移动、沙箱另见下文。

## 依赖

| 组件 | 说明 |
|------|------|
| Go 1.22+ | `services/api` |
| Python 3.11+ | `services/agent-runtime`（用 `.venv`） |
| Node + pnpm | `apps/web`（及 desktop/mobile） |
| Docker | Postgres（`pgvector/pgvector:pg16`）；沙箱镜像可选 |

桌面另需 Rust（rustup）+ Xcode CLT；移动另需 Xcode / Android Studio。

## 一次性准备

```bash
# 1) 环境变量（已有 .env 可跳过）
cp .env.example .env
# 至少确认：DATABASE_URL、JWT_SECRET、OPENAI_BASE_URL / OPENAI_API_KEY / OPENAI_MODEL
# 记忆召回可选：EMBEDDING_*
# 沙箱可选：SANDBOX_ENABLED / SANDBOX_IMAGE / SANDBOX_DATA_ROOT
# 会话文件持久化（可选）：SANDBOX_S3_ENDPOINT=http://127.0.0.1:9000
# 未设置 endpoint 时只用本地 SANDBOX_DATA_ROOT。见 docs/沙箱电脑.md

# 2) Postgres
make compose-postgres
# 或：docker compose -f deploy/compose.yaml --project-directory deploy up -d postgres
# 默认：postgres://openbot:openbot@127.0.0.1:5432/openbot?sslmode=disable

# 3)（可选）沙箱电脑镜像
make sandbox-image           # openbot-sandbox:dev
make sandbox-image-desktop   # Xvfb+noVNC 桌面镜像；或 .env 换 webtop + SANDBOX_DESKTOP_PORT=3000
```

若 Postgres 从官方镜像升级到 pgvector，开发环境可：

```bash
make compose-down
docker volume rm deploy_openbot_pg   # 会清空库数据
make compose-postgres
```

全部 **core** compose 依赖（Postgres / Redis / MinIO / MarkItDown；不含 casdoor/langfuse profile）：

```bash
make compose-up
# 一次起 core + Casdoor + Langfuse：make compose-all
```

## 日常启动（三个终端）

```bash
# 终端 A — Agent 运行时  http://127.0.0.1:8001
make dev-runtime

# 终端 B — Go 产品 API   http://127.0.0.1:18080
make dev-api

# 终端 C — Web 用户端   http://127.0.0.1:5173
make dev-web

# 终端 D — 管理端（可选） http://127.0.0.1:5174
make dev-admin

# （可选）终端 D — Routines worker（独立进程）
# 建议 API 侧设置 ROUTINES_INPROCESS=0 避免与进程内 scheduler 双触发
make dev-worker
```

浏览器打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)，注册/登录后即可聊天。

### Routines worker

- 默认：API 进程内每分钟 tick（`ROUTINES_INPROCESS` 非 `0`）。
- 独立 worker：`make dev-worker` → `go run ./cmd/worker`，轮询 due routines，调用 `POST /internal/routines/run`。
- 环境：`OPENBOT_API_URL`、`INTERNAL_TOKEN`、`WORKER_POLL_SECONDS`（默认 30）、`DATABASE_URL`。

例行任务现支持：
- **IANA 时区**（默认 `Asia/Shanghai`），cron 按该时区对齐分钟。
- **固定会话**：首次触发创建「例行 · 名称」会话并写入 `routines.conversation_id`；之后复用，消息带 `[routine]` 提示。
- **事件唤醒**：设置 → 例行任务 →「入站 Webhook」创建 Hook，把
  `http://<api>/v1/webhooks/slack/<token>` / `.../github/<token>` 配到 Slack Event Subscriptions / GitHub Webhooks。
  例行的 `triggers` 示例：
  `[{ "source": "slack", "type": "app_mention" },`
  `{ "source": "slack", "type": "keyword", "keywords": ["日报"] },`
  `{ "source": "github", "type": "pull_request", "actions": ["opened"], "repo": "org/repo" }]`。
  GitHub 可在创建 Hook 时填 `secret`，对应 `X-Hub-Signature-256`。
- **聊天工具**：`create_routine` / `update_routine` / `pause_routine` / `resume_routine` / `delete_routine` / `list_routines`；
  长任务用 `defer_work(goal=…)` 先确认再后台（同会话交付，约 30 分钟超时）。
- 失败按 `max_retries` 重试；`quiet_unchanged` 时结果哈希不变记为 `ok_quiet`。
- UI 文案：「电脑」= 用户真实设备；「运行环境」= Bot 共用执行环境。禁止对用户说 sandbox/Docker/容器/工作电脑。

### Web 聊天 UI

浅色 OpenClaw 风格聊天界面；视觉参考见 [`docs/ui-reference-openclaw-chat.png`](./ui-reference-openclaw-chat.png)。
改 `apps/web` 后若 Vite 已在 `:5173`，HMR 一般会自动刷新；样式/结构大改时请硬刷新（Cmd+Shift+R）。

**信息架构（Grok / Rakazo 助手级）**：侧栏主列表是「助手」+「群聊」，不是会话堆。点助手会 `GET /v1/agents/{id}/conversation` 打开（或创建）该助手的一条连续主线程；「+」里选助手同样是打开主线程。

**作曲框**

- 群聊里输入 `@` 可点名成员或 `@everyone`（全体回复）；无 `@` 时仍由第一位成员回复；非 everyone 时本回合仅第一位被 @ 的 Bot 回复（单阶段 owner）。
- 单聊里 `@其他 Bot` 会切到对方主线程再发送：原会话留下转交记录（原 Bot 下次仍看得见）；对方会带上近期对话上下文（不写入对方历史）。
- `/`：弹出当前 Bot 已启用的 Skills，插入 `请 load_skill <name>`。
- 写代码岗（引导 D）默认启用改编自 [mattpocock/skills](https://github.com/mattpocock/skills) 的 `diagnosing-bugs` / `tdd` / `implement` / `code-review`，以及 `dev-assist`（入口）、`host-ssh`、`summarize-text`；可在「设置 → 当前 Bot」再开其它账号 Skill。
- 「从对话存 Skill」入口默认关闭（设置 → Skills 仍可手动上传）。

**引导与岗位**

- 新助手空会话会出现 A–E 引导卡；选项会 `POST /v1/agents/{id}/onboarding` 写入岗位描述、人设与默认 skill 集，再发送首条用户消息。
- 设置 →「当前 Bot」：编辑岗位/人设、`computer_mode`（team 共享 / private 私有）、本 Bot Skills 开关。
- 设置 →「Skills」仍为账号级启用；运行时取 **账号启用 ∩ Bot 允许列表**。
- 设置 →「例行任务」须选所属 Bot（默认当前助手）。
- 设置 →「插件 / MCP」为账号级连接器；「运行环境」确保启动时带当前 Bot 的 `agent_id`/`computer_mode`。


### 运行状态动画 + 聊天附件（一期）

- **运行状态**：发消息后，消息列表底部显示彩色动画 blob +「正在思考…」/「正在运行命令」；来自 runtime SSE `event: status`（`phase=thinking|tool|tool_done`）。硬刷新（Cmd+Shift+R）后再试。
- **附件**：作曲栏左侧圆形「+」多选上传；`POST /v1/conversations/{id}/attachments`（单文件 ≤20MB，图片/文本/PDF/DOCX/XLSX/PPTX/JSON/MD/CSV/代码类 MIME）；发送可仅附件或文本+附件。文本类会截断内联进 user 消息。PDF/DOCX/XLSX/XLS/PPTX 在 `DOC_PARSE_URL` 指向 MarkItDown（`make compose-up` 的 `:8010`）时抽出 Markdown，仅注入当次模型输入（不改写会话消息）；管理端「运维 → 附件解析」可配超时。未配置或解析失败只写说明，不编造正文。**无 OCR、无 RAG**。**图片未接视觉多模态**（仅文件名提及）。无麦克风。详见 [附件文档解析-MarkItDown.md](./附件文档解析-MarkItDown.md)。
- 参考图：[`docs/ui-reference-thinking-attach.png`](./ui-reference-thinking-attach.png)。

## Langfuse（可观测 / traces）

独立 Docker **profile**（`deploy/compose.yaml` 的 `langfuse`；**不**共用 open-bot 的 Postgres/Redis/MinIO），基于官方 Langfuse **v4** 镜像。Compose 内库连接变量名为 `LANGFUSE_DATABASE_URL`（主机名 `langfuse-postgres`；避免与仓库根 `.env` 的 `DATABASE_URL` 插值冲突）；`make compose-langfuse` 会 `env -u DATABASE_URL`。详见 [deploy/README.md](../deploy/README.md)。

| 服务 | 主机端口 | 说明 |
|------|----------|------|
| Langfuse Web UI | `http://localhost:3100` | `NEXTAUTH_URL=http://localhost:3100` |
| Langfuse worker | `127.0.0.1:3030` | 内部 |
| Langfuse Postgres | `127.0.0.1:5433` | 避开 open-bot `:5432` |
| Langfuse Redis | `127.0.0.1:6380` | 避开 open-bot `:6379` |
| Langfuse MinIO | `:9090` / `:9091` | 官方习惯；ClickHouse native `:9000` **不**映射到主机（避开 open-bot MinIO） |
| ClickHouse HTTP | `127.0.0.1:8123` | |

### 打开 tracing

根目录 `.env`：

```bash
LANGFUSE_PUBLIC_KEY=pk-lf-openbot-local
LANGFUSE_SECRET_KEY=sk-lf-openbot-local-dev-change-me-not-for-prod
LANGFUSE_BASE_URL=http://127.0.0.1:3100
# 可选：无 key 时强制开（仍需 key 才会真正上报）
# LANGFUSE_ENABLED=1
```

然后重启 runtime：

```bash
make stop-runtime && make dev-runtime
```

发一条聊天 → 打开 [http://localhost:3100](http://localhost:3100) → 项目 **open-bot** → Traces，应看到 `open-bot.run`（含嵌套 LLM generation / tool）。

LLM 输入默认会记录 **完整 system**（persona + tools routing + memory + client_env，以及合并后的对话摘要）；生产可设 `LANGFUSE_REDACT_SYSTEM=1` 只保留 `[omitted system prompt, N chars]`。Public API v2 拉 observation 时需加 `fields=core,io`，否则 `input`/`output` 默认为空（events_only 列表视图）。


Traces 会带上 **user_id**（登录用户）与 **session_id**（= `conversation_id`）。当上游 OpenAI 兼容网关在非流式 `chat/completions` 响应里返回 `usage`（`prompt_tokens` / `completion_tokens` / `total_tokens`）时，会写入 generation 的 **usage_details**，可在 Langfuse 里按用户 / 会话查看 token 用量。流式 fallback 路径目前多数网关不带 usage，此时该字段会留空（不会填假 0）。

在 UI 中按用户过滤：Traces → Filters → **User**（或打开某条 trace 看 User / Session）；用量在 generation 观察的 Usage 区域。

关闭：去掉 keys 或 `LANGFUSE_ENABLED=0`；SDK **soft-fail**，不影响 Mem0/tools/聊天。

## Agent 内置工具

默认 **关闭**（`.env` 中 `OPENAI_ENABLE_TOOLS=0`）。开启后需重启 runtime：

```bash
# .env
OPENAI_ENABLE_TOOLS=1
make stop-runtime && make dev-runtime
```

内置工具（与 `sandbox_*` / MCP 一并注入）：

| 工具 | 作用 |
|------|------|
| `get_current_time` | 时区感知当前时间（默认 `Asia/Shanghai`，或 `TZ` / `OPENBOT_TZ`） |
| `calculator` | 安全算术表达式（仅数字与 `+ - * / ** % //` 与括号） |
| `http_fetch` | 受限 HTTP GET 文本；默认拒绝私网/回环/链路本地/元数据 IP（SSRF）；本地调试可设 `HTTP_FETCH_ALLOW_PRIVATE=1` |

本地 vLLM 若要用 tools，需启动参数 `--enable-auto-tool-choice` 与 `--tool-call-parser hermes`（Qwen/Hermes 风格）。若未设置，上游会 400；runtime 会**自动降级为本轮无 tools 的普通补全**，聊天仍可回复，但不会真正调用工具。也可在连接上关闭 `enable_tools` / 设 `OPENAI_ENABLE_TOOLS=0`。

## Casdoor（多用户与管理端）

Compose profile `casdoor`（`deploy/compose.yaml`；**不**共用 open-bot Postgres）：

| 服务 | 主机端口 |
|------|----------|
| Casdoor UI / OIDC | `http://localhost:8000` |
| Casdoor Postgres | `127.0.0.1:5434` |

```bash
make compose-casdoor
# 停止：make compose-casdoor-down
```

首次打开 Casdoor：账号 `built-in/admin` / 密码 `123`。

1. **Applications → app-built-in**：复制 Client ID / Secret  
2. Redirect URLs 增加：`http://127.0.0.1:5173/auth/callback`、`http://localhost:5173/auth/callback`  
3. 写入仓库根 `.env`：

```bash
CASDOOR_ENDPOINT=http://127.0.0.1:8000
CASDOOR_CLIENT_ID=...
CASDOOR_CLIENT_SECRET=...
CASDOOR_REDIRECT_URI=http://127.0.0.1:5173/auth/callback
CASDOOR_ORGANIZATION=built-in
CASDOOR_APPLICATION=app-built-in
```

4. 重启 `make dev-api`（`GET /healthz` 中 `oidc_enabled: true`）  
5. Web 登录页出现「用 Casdoor 登录」。**新注册用户一律为 `member`（聊天端）**；运营管理员请用 `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD`（见 `.env.example`）或既有 `org_admin`/`platform_admin`。  
6. 运营另开终端 `make dev-admin`，浏览器**直接**打开 **http://127.0.0.1:5174**，走管理端登录（`POST /v1/admin/auth/login`）。普通 `member` 会被 403。用户端**不再**提供「管理端」入口。详见 [多用户与管理端.md](./多用户与管理端.md)#怎么进入管理端登录  
7. 邀请终端用户：管理端 → 成员 → 角色选「成员（终端用户）」→ 对方在 `:5173` 注册/Casdoor 登录后入组。邀请管理员账号时再选组织/平台管理员。

本地密码登录始终可用（未配 Casdoor 时无 OIDC 按钮）。Casdoor `:8000` 是 IAM，不是业务管理端。

## 多模型兼容

agent-runtime 通过 `model_compat` 按 **model / base_url** 识别家族，适配 `/v1/chat/completions` 的 tools + reasoning 字段（仍走 OpenAI 兼容 HTTP，不做 Anthropic Messages 重写）。

| family | 识别示例 | 带 tools 时要点 |
|--------|----------|-----------------|
| `openai_chat` | gpt-4o、gpt-4.1、chatgpt-* | 正常 `tool_choice=auto`；不塞 `reasoning_effort` |
| `openai_reasoning` | o1/o3/o4、gpt-5*、*luna*、*-thinking*、含 reasoning | **`reasoning_effort=none`**；去掉 temperature/top_p |
| `anthropic` | claude*；URL 含 anthropic.com | tools 可用；走兼容网关 |
| `qwen` | qwen*、qwq*；URL 含 dashscope | **省略 `tool_choice=auto`**；剥 `<think>` |
| `deepseek` | deepseek* | 剥 `<think>`；保留 tool_choice auto |
| `compat` | 其它 / 本地 vLLM | 省略 `tool_choice=auto`；剥 `<think>` |

环境变量覆盖（见 `.env.example`）：

| 变量 | 作用 |
|------|------|
| `OPENAI_MODEL_FAMILY` | 强制家族（上表之一） |
| `OPENAI_REASONING_EFFORT` | 无 tools 时的 `reasoning_effort`；空字符串=不传 |
| `OPENAI_REASONING_EFFORT_WITH_TOOLS` | 有 tools 时覆盖；空字符串=不传 |
| `OPENAI_TOOL_CHOICE_AUTO` | `0`/`1` 强制是否发送 `tool_choice=auto` |

**luna / tools**：若上游仍 400 且 body 含 `reasoning_effort`，`chat_completion` 会再重试一次 `reasoning_effort=none`。若 400 提示需要 `--enable-auto-tool-choice` / `--tool-call-parser`，`run_tool_loop` 会**再试一次不带 tools** 的补全，并经 SSE status 提示本轮禁用 tools。改完后若 runtime 开了 `--reload` 会自动加载；否则 `make stop-runtime && make dev-runtime`。

在 `.env` 设置 `BOT_SECRETS_KEY` 或 `ENCRYPTION_KEY`（AES-GCM）。Web：设置 → **密钥**；助手工具 `request_secret` / `secret_http`。列表 API 只返回元数据。


## 上下文压缩（token 预算）

对话压缩优先按**估算 token** 相对模型上下文窗口触发（不再只靠消息条数/字符数）：

| 变量 | 默认 | 说明 |
|------|------|------|
| `COMPACT_DEFAULT_CONTEXT_WINDOW` | `32768` | 未配置连接窗口且模型名无法推断时的默认窗口 |
| `COMPACT_BUDGET_RATIO` | `0.75` | 可用预算 = 窗口 × ratio − 预留输出 |
| `COMPACT_RESERVE_OUTPUT_TOKENS` | `2048` | 为模型输出预留的 token |
| `COMPACT_MAX_MESSAGES` / `COMPACT_MAX_CHARS` | `20` / `6000` | 遗留兜底阈值 |
| `COMPACT_KEEP_RECENT` | `8` | 压缩时尽量保留的最近消息数（也可按 token 切片） |

在 Web **设置 → LLM** 可为每条连接填写「上下文窗口 (tokens)」（留空=按模型名自动推断）。**设置 → 压缩** 只读展示当前阈值与估算预算。

## 记忆 embedding 回填

对 `memories.embedding IS NULL` 的行批量调用 `EMBEDDING_*`（幂等，按批更新）：

```bash
# 预览
```

## 本地 Dream（记忆整理）

- **默认开启**：Mem0 OSS 自动抽取 + **本地 Dream** 默认开启（`MEM0_DREAM_ENABLED=1`，与 `MEM0_ENABLED` 同模式）。成功回复后后台自动整理近期事实为 `tier=profile` / `tag=dream` 的 durable 摘要；按用户节流（`MEM0_DREAM_INTERVAL_SECONDS`，默认 3600，不每条消息都跑）。
- **关闭**：`.env` 设 `MEM0_DREAM_ENABLED=0`（或 `false` / `off`）。
- **embedding 回填**：仍手动，`make backfill-embeddings`（见上一节）。
- **Platform Dream**：可选；需 `MEM0_PLATFORM_API_KEY`（或 `MEM0_API_KEY`）且 `MEM0_PLATFORM_DREAM=1`。此时 `dream_mode=platform`；当前 runtime **不会**调用托管 Dream API（请在 Mem0 Platform 控制台使用，或设 `MEM0_PLATFORM_DREAM=0` 回到本地自动整理）。
- **运维补跑**：`make dream-user` 为 escape hatch（强制单次整理，不依赖间隔）。

```bash
# 关闭本地 Dream
# MEM0_DREAM_ENABLED=0

# 调整自动间隔（秒，下限 60）
# MEM0_DREAM_INTERVAL_SECONDS=3600

# 运维：立即整理某用户（忽略「是否刚跑过」的自动间隔）
make dream-user USER_ID=<users.id>
# healthz 可见 dream_mode / dream / interval_seconds
```
