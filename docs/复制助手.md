# 复制助手（Clone Bot）

把一个助手复制成新助手（新的 `agent_id`），归属**同一用户**，因此天然不跨用户 / 组织。

> **记忆默认**：新任务若与过去工作相关，副本需要助手专属记忆；因此 Web / `clone_agent` 默认复制 bot 记忆，交接任务（`follow_up`）时强制复制。

## 入口

| 入口 | 说明 |
|------|------|
| Web 侧栏 | 助手行悬停 → 「复制」图标 → 弹窗（可改名、可勾选记忆 / 例行任务）→ 复制后自动打开新助手 |
| Web 设置 → Bot | 「复制助手」按钮，同一弹窗 |
| 单聊里让助手自己复制 | 用户说「复制一个你」「再来一个一样的，专门写周报」「复制后让新的去查 X」→ 模型调用 `clone_agent` |
| 管理端 Bot 管理 | 「复制」（同一成员名下；不复制记忆 / 例行任务，不派任务） |

API：`POST /v1/agents/{id}/clone`（用户）、`POST /internal/agents/clone`（runtime 工具）、`POST /v1/admin/bots/{id}/clone`（组织管理员，写审计 `bot.clone`）。

## 复制什么

| 类别 | 处理 |
|------|------|
| 名称 | 默认「原名 副本」，重名递增「副本 2」；可指定 |
| 岗位描述、人设（system_prompt）、电脑模式 | **复制**（可覆盖；工具支持 `system_prompt_append` 在原人设后追加） |
| 本助手 Skills 开关（`agent_skills`） | **原样复制**；原助手没有单独设置时，副本同样沿用账号启用的全部技能；可用 `enable_skills` / `disable_skills` 调整 |
| 用户级记忆、账号技能库 / 自定义技能、模型连接、MCP、已登记电脑、用户设置、team 工作区 | **共享**（账号级，不需要复制） |
| 助手专属记忆（`memories.scope='bot'`） | **默认复制**（Web 勾选默认开；`clone_agent` 的 `copy_memory` 默认 true）。用户可取消勾选 / 显式 `false`。当设置了 `follow_up`（交接 / 后续任务）时**始终复制**，即使传 `false`，以便副本承接与过去相关的工作。只复制 Postgres 里的显式 bot 记忆（含 embedding）；Mem0 自动记忆不复制 |
| 例行任务 | 默认**不复制**；勾选 / `copy_routines=true` 时复制，**一律暂停**（避免同一 cron / 事件触发两次），原来绑定会话的改绑到副本的主会话 |
| 聊天记录、线程、群聊成员身份、助手间（agent_pair）记忆 | **不复制** |
| 助手密钥（`bot_secrets`） | **不复制**，需要在副本里重新授权 |
| private 模式的私有文件、后台任务、用量统计、agent-bus 消息 | **不复制** |

## 「复制后再做 X」

`clone_agent(follow_up="…")`（别名 `handoff_task`）：副本创建后，在**副本自己的主会话**里写一条用户消息（注明来自哪位助手）并排入后台任务队列（与 `defer_work` 同一套），由副本用自己的人设与技能完成并回报。原助手不代做。有 `follow_up` 时会**强制复制**助手专属记忆（即使 `copy_memory=false`），方便新任务衔接旧工作。这是新建副本接手任务，不是本回合向另一位已有 Bot 提问；后者用 `ask_agent`。

## 约束

- 工具只在单聊可用：群聊或助手间对话中调用会被拒绝。
- 只能复制自己（当前 `agent_id`）；Go 侧再按 `user_id` 校验归属。
- 复制成功后 API 通过聊天事件 WebSocket 推 `agents_changed`；Web 在 `useChatEventsSocket` 收到后 `refreshAgents()`，侧栏自动刷新（与创建/删改 Bot、群聊变更同一路径）。
