# 目录说明

本仓库按「多端产品 + 产品 API + Agent 运行时」拆分，Phase 1 尽量少挪目录。

## 为何这样拆

| 路径 | 职责 |
|------|------|
| `apps/` | 用户界面。`web` 聊天/设置（终端用户）；**`admin` 业务管理端**（仅运营，与 web 登录分离）；`desktop` 为 Tauri 2 壳（复用 web）；`mobile` 为 Capacitor 7 壳（复用 `apps/web/dist`）；**`mobile-rn` 为 React Native 原生移动端**（Expo + HeroUI Native，独立实现 UI，仅复用后端契约）。 |
| `services/api` | **Go 产品 API**：鉴权（后续）、会话、CORS、SSE 扇出、多助手总线入口。对外稳定契约，不嵌入 LLM 细节。 |
| `services/agent-runtime` | **Python Agent 运行时**：模型调用、Skills、Memory、Compaction、MCP（后续 LangGraph）。对内协议，可独立演进。 |
| `packages/openapi` | API 契约草案，前后端对齐用。 |
| `skills/` | Agent Skills 技能包（`SKILL.md`）。 |
| `deploy/` | `compose.yaml`（profiles：core / casdoor / langfuse）；**`deploy/casdoor` 仅 IAM 配置**，不放业务 Admin UI。见 [deploy/README.md](../deploy/README.md)。 |
| `docs/` | 技术方案、[本地启动](./本地启动.md)、沙箱与缺口说明。 |

## Go / Python 边界

- **浏览器只打 Go**（默认 `http://127.0.0.1:18080`），不直连 Python。
- Go 负责：会话与消息的产品侧存储（Phase 1 为内存）、代理 `POST /v1/runs` 的 SSE，并把 token 拼成 assistant 消息落库。
- Python 负责：真正「跑助手」——有 `OPENAI_API_KEY` 时走 OpenAI 兼容 Chat Completions 流式；无 key 时 echo，并在 meta 标明 `mode: echo`。
- 这样换模型、换编排框架不必改前端与产品 API 面。
